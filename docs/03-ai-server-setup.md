# 03. 让本地 AI 分阶段配置服务器

SSH 打通以后，我没有继续手打一长串 Shell，而是让 Codex 一类的本地 AI Agent 直接通过 SSH 检查和配置服务器。

它可以完成的事情很具体：

- 登录服务器并读取系统状态
- 执行 `apt update` 和必要的安全更新
- 安装软件、写配置文件
- 检查 systemd 服务和监听端口
- 查看日志，遇到错误继续定位
- 修改后再次验证，而不是只说“应该可以”

这种方式省事，但前提是任务边界写清楚。AI 有执行权限时，一句含糊的“帮我优化服务器”并不安全。

## 我实际采用的顺序

1. 只读检查系统、端口、SSH 和防火墙。
2. 更新软件索引，只安装必要安全更新。
3. 确认 SSH Key 登录正常后，再关闭密码登录和 root 远程登录。
4. 部署 sing-box，并先验证配置语法和 systemd 状态。
5. 确认 SSH 22 一直允许，再放行 Reality 使用的 TCP 443。
6. 服务端稳定后，读取真实配置生成客户端资料。
7. 最后再加分流规则和本地流量统计。

## 几条很实用的限制

- 一开始不要让 AI 随便改 SSH。先要求它证明当前 Key 登录正常，并在 reload 前验证 sshd 配置。
- 每轮只做一类事情。SSH、防火墙、节点协议和客户端配置不要塞进一次任务。
- 修改 UFW 前明确要求保留 TCP 22，否则一次错误就可能把自己挡在门外。
- 不运行来源不明的一键脚本。安装来源、版本和配置位置都应该说清楚。
- 重要操作采用“先检查、再修改、最后验证”的顺序。
- 不确定时先发一个“只读检查”任务，确认现状后再决定是否改。

我也会把不能做的事情直接写进提示词，例如“不升级整个 Ubuntu 发行版”“不要重新生成 UUID”“不要开放全部端口”。这比事后补救有效得多。
